# Obsidian 记忆库（通用版）

**这是什么**：一套可复制的「AI 长期记忆」方案。记忆本体是一个 **Obsidian 库 + git 仓库**，任何 Agent 进去读，人和 Obsidian 也能直接看。

**两段式**：

- **第一次用** → 建库（第 1 节）：目录、模板、索引、访谈、接线。
- **之后每次** → 维护（第 2~5 节）：每日整理、周复盘、即时落盘、体检。

**定位**：记忆的价值在「变化点 + 结论」，不在「聊天记录」。写清楚一件决定，胜过存一百条原文。

---

## 0. 三十秒判断：库在哪、建了没

1. 读当前目录 / 用户给出的路径下的 `.memory/config.json`；
2. **有** → 读 `00-首页.md` 和 `01-读取与更新规程.md`，按其口径干活（本技能与它一致，冲突时以库里规程为准）；
3. **没有** → 问三个问题（称呼 / 库放哪 / 用哪些 AI），走第 1 节建库。

---

## 1. 建库（首次）

```powershell
pwsh -NoProfile -File '<技能目录>\scripts\init-vault.ps1' -Vault '<库根>' -Owner '<称呼>'
```

脚本建出 8 个目录、15 个文件（首页 / 规程 / 三套模板 / 四个索引 / 核心记忆三篇 / 收件箱说明 / 库内 AGENTS.md / `.memory/config.json`），并 git 首次提交。

然后按 `references/init.md` 做 **8 问访谈**，把 `10-核心记忆/` 填实——**不填，这个库就只是个空壳**。

非 Windows 或没有 pwsh：照 `references/init.md` 列的结构手工建，把 `assets/templates/*.md` 复制进去、替换 `{{OWNER}}` / `{{VAULT}}` / `{{DATE}}` / `{{TZ}}`。

---

## 2. 每日整理

**七步**（细节见 `references/daily.md`）：

1. 读今天涉及的项目笔记（只读涉及的）；
2. 写 / **追加** `30-每日记录/YYYY-MM-DD.md`（结构固定四块：📮 沟通要点 / 🔄 项目变动 / ✅完成·⏳待办 / 🧷 备注）；
3. 变化点同步进 `20-项目/*.md`，改 `更新` 日期；
4. 总览状态列有变动才改；
5. 收件箱归档 `99-收件箱/_已处理/YYYY-MM/`；
6. 值得沉淀的方法进 `50-沉淀库/_索引.md` 候选（**不当天硬写**）；
7. 收尾 + 提交。

**没新内容就跳过**，回一句「今日无新记忆」——不要为了产出而造记录。

---

## 3. 每周复盘

1. 通读本周 7 天每日记录（上一周的复盘只看「下周计划」对账）；
2. 写 `40-周复盘/YYYY-Www.md`（ISO 周，周一起算）：主线 3~5 条 / 净变化表 / 卡点排序 / P0-P1-P2；
3. 净变化回写项目笔记（一段，不复制全文）；
4. 够格的沉淀进 `50-沉淀库/`，更新索引；
5. 体检 + 收尾。

**净变化写「从 X 到 Y」**，不写「现状是 Y」；下周计划写能验收的动作，不写「继续推进」。

---

## 4. 「记住」= 立即落盘

用户说「记住 / 记一下 / 帮我记 / remember this」：

1. **判断去向**：偏好 → `10-核心记忆/`；项目事实 → `20-项目/`；不确定 → `99-收件箱/YYYY-MM-DD-主题.md`；
2. **落盘**，改 `更新`，只写要点不抄原话；
3. **回复路径**：「记在 `<路径>`」；
4. 只记事实 / 决定 / 偏好；他人隐私与凭证不落。

**口头答应不算记住，文件里有了才算。**

---

## 5. 体检

```powershell
pwsh -NoProfile -File '<技能目录>\scripts\check-vault.ps1' -Vault '<库根>' -Days 7
```

查五类：断链、frontmatter 缺「更新」、最近 N 天每日记录缺口、已结束周的周复盘缺口、索引漏登记。

- `-Json` 出结构化结果；`-Strict` 有问题时退出码 1（可放进定时任务）。
- 不传 `-Vault` 时，从当前目录向上找 `.memory/config.json` 自动定位。
- 只读，不改库。缺口是**漏跑信号**，按日期归位补（每日 ≤7 天、每周 ≤21 天），补的标「（补整理）」。

---

## 6. 写入规范（要点）

- frontmatter 中英统一：`创建` / `更新`；每次改内容改 `更新`。
- 双链 `[[路径|别名]]`，表格里写 `\|`；新笔记必须登记进索引，否则 Obsidian 图谱里是孤岛。
- **只写变化点**：数字要能回溯（版本 / 提交 / 金额 / 用例数）。
- 不确定标 `（待核实）`；矛盾并列不擅自定稿。
- **不改历史日记**：更正写在新记录 + 首页变更日志。
- 隐私红线：他人隐私不提炼、不外传；密码 / token / 证件号不落盘。
- 不动 `.obsidian/`；重命名用 Obsidian（会连带更新双链）。

细节见 `references/writing-rules.md`，好 / 坏样例见 `references/examples.md`。

---

## 7. 反模式

| 别做 | 正确做法 |
|---|---|
| 全库通读 | 首页 → 索引 → 单篇（L0→L1→L2） |
| 把聊天原文贴进笔记 | 只留要点 + 出处 |
| 一天写多篇 / 补记塞进今天 | 一天一篇，按日期归位，同日追加 |
| 用今天的口径改写历史日记 | 历史留原文，写「更正」条目 |
| 没新内容也硬写 | 跳过，密度比数量重要 |
| 建了库不填核心记忆 | 访谈是建库的一部分，不是可选项 |
| 门文件里写隐私 | 指针只放路径和协议 |
| 说完「记住了」没写文件 | 落盘 + 回复路径 |

---

## 8. 接线（让所有 Agent 都读得到）

原则：**记忆本体一份，每家只装一扇门 + 一个技能**。

- 门 = 全局指令文件里的一段指针（只含路径与读取协议）；
- 技能 = 本目录复制进 `~/.agents/skills`、`~/.claude/skills`、`~/.codex/skills` 等；
- **坑**：技能 `name` 必须是 ASCII 短横线名，中文名会被静默跳过。

具体路径表、门模板、定时任务写法见 `references/wiring.md`。

---

## 9. 交付前自检（6 问）

1. 每条变化点，都能在项目笔记里找到落点吗？
2. 有没有数字没出处？
3. 有没有把「应该」写成「已经」？
4. 同一事实是否只存了一处？
5. 索引 / 首页 / 待办同步了吗？
6. git 提交了吗？没提交有没有说明原因？
