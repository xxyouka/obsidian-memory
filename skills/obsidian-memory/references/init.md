# 建库（首次使用）

> 触发：目标目录里没有 `.memory/config.json`，或用户说「帮我建个记忆库 / 想要一个能记住我的库」。
> 目标：**10 分钟内**得到一个能立刻开始记的库，而不是一个空目录。

## 0. 先问三个必答

1. **怎么称呼你？**（进首页标题、库内 AGENTS.md、偏好文件）
2. **库放哪？**（默认 `%USERPROFILE%\记忆库` 或 `~/记忆库`；路径别带空格更省事；必须是 Obsidian 能打开的普通文件夹）
3. **你主要用哪些 AI 工具？**（Claude Code / Codex / Cursor / Trae / DSH / OpenCode… 决定第 5 步怎么接线；不确定就先按「只用手动」）

一次问完，别连环追问。其余信息靠第 2 步访谈慢慢补。

## 1. 建结构（一条命令）

```powershell
pwsh -NoProfile -File '<技能目录>\scripts\init-vault.ps1' -Vault 'D:\记忆库' -Owner '小王'
```

产出（15 个文件 + 8 个目录）：

```
<库根>/
├─ 00-首页.md                  # 总入口（MOC）
├─ 01-读取与更新规程.md         # 规则
├─ AGENTS.md                   # 库内给 Agent 的规矩
├─ .memory/config.json         # 库配置：owner / vault / 时区 / 例程
├─ 10-核心记忆/  _索引 + 关于我 + 偏好与沟通风格 + 雷区与红线
├─ 20-项目/     _项目总览
├─ 30-每日记录/ _索引
├─ 40-周复盘/   _索引
├─ 50-沉淀库/   _索引
├─ 90-模板/     每日记录 / 周复盘 / 项目笔记
└─ 99-收件箱/   _说明 + _已处理/
```

- 目录已有内容时脚本会拒绝，需要覆盖加 `-Force`；不想要 git 加 `-NoGit`。
- **非 Windows**：没有 pwsh 就手工照上面的结构建目录，把 `assets/templates/*.md` 复制进去，替换 `{{OWNER}}` / `{{VAULT}}` / `{{DATE}}` 占位符。

## 2. 访谈（8 个问题，一次问 2~3 个）

| 问什么 | 写进哪 |
|---|---|
| 你是做什么的？现在主要在忙什么？ | `10-核心记忆/关于我.md` → 身份与在做的事 |
| 一年内最想完成的事？ | `关于我.md` → 长期目标 |
| 希望 AI 怎么称呼你、什么语气、回复多长？ | `偏好与沟通风格.md` → 沟通偏好 |
| 常用什么工具 / 系统 / 语言？ | `偏好与沟通风格.md` → 工作习惯 |
| 要成品还是选项？文件怎么命名？ | `偏好与沟通风格.md` → 交付偏好 |
| 有什么事绝对不要做？ | `雷区与红线.md` → 绝对不要 |
| 有哪些隐私 / 公司数据不能写？ | `雷区与红线.md` → 隐私红线 |
| 现在有哪些长期项目？ | `20-项目/_项目总览.md` 登记 + 每项目一篇 |

**访谈三条纪律**：

- 用户说的原话要**转成长期有效的事实**，不要抄对话；
- 拿不准的写 `（待核实）`，别编；
- 每问完一批就落盘，不要攒到最后一起写。

## 3. 第一条记忆（演示闭环）

建完库，请用户说一件「希望我记住的事」，当场走一遍：

1. 判断去向（偏好 → 10-核心记忆；项目 → 20-项目；不确定 → 99-收件箱）；
2. 落盘，改 frontmatter `更新`；
3. 回复「记在 `<路径>`」。

这一步让用户看到**落盘是真的**，后面才会信这个库。

## 4. 验收

- `check-vault.ps1 -Vault <库根>` 全绿（新库不报缺口）；
- 用 Obsidian 打开这个文件夹 → 能看到笔记和图谱；
- 另开一个 AI 会话问「我的永久记忆库在哪？读一下首页说说分区」→ 能答出来（没接线就答不出来，走第 5 步）。

## 5. 接线

编译到全局指令、装技能、可选定时任务 —— 见 `wiring.md`。

## 6. 交付话术（给用户的一句话）

> 库建在 `<路径>`，已经 git 提交。以后你说「记住」，我就写进去；每天/每周我可以整理一次。要不要现在就接给你常用的那几个 AI？
