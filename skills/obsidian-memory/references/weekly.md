# 每周复盘 · 逐项清单

> 目标：把 7 天的流水压成「主线 + 净变化 + 卡点 + 下周 P0」。复盘的价值在**取舍**，不在汇总。

## A. 周次与窗口

- ISO 8601，周一为第一天。例：`2026-W43` = 2026-10-19（周一）～ 10-25（周日）。
- 周次写 `YYYY-Www`（两位数补零）；文件名 `40-周复盘/YYYY-Www.md`。
- 快算：PowerShell `[System.Globalization.ISOWeek]::GetWeekOfYear((Get-Date))`。

## B. 通读范围

- 本周 7 篇每日记录（必读）。
- 上一周复盘（只看「下周计划」，对账：上周 P0 完成了没有）。
- 不重读项目笔记全文，除非写净变化时要核对数字。

## C. 写作顺序

1. **本周主线**：3~5 条，每条 = 一句判断 + 关键数字。要能回答「这周到底推进了什么」。
2. **各项目净变化**（表格）：项目 / 净变化 / 下周要点。写「从 X 到 Y」，不写「现状是 Y」。
3. **卡点 / 风险**：按「有硬截止 > 有真实风险 > 拖着没动」排序；每条写清后果。
4. **下周计划**：P0（带日期或后果，≤3 条）/ P1（该做）/ P2（可选）。
5. **沉淀候选**：本周有哪些「可复用 + 已验证 + 有自己的话」的方法。
6. **健康检查**：跑脚本 + 人工四项（见 D）。
7. **补漏**（若上周漏跑）：用一段「📎 补漏」覆盖，别拆成多篇。

## D. 健康检查

**先跑脚本，别手搓**：

```powershell
pwsh -NoProfile -File '<技能目录>\scripts\check-vault.ps1' -Vault '<库根>' -Days 7
```

输出五段：断链 / frontmatter / 每日记录缺口 / 周复盘缺口 / 索引漏登记。`-Json` 出结构化结果，`-Strict` 有问题时退出码 1。

脚本覆盖不到的四项，人工判断：

- **过时**：首页待办、项目「当前版本 / 当前状态」、各种截止日期。
- **重复**：同一事实在每日 + 项目 + 沉淀各写一次 → 只留最权威那处，其余改双链。
- **口径冲突**：并列两种说法 + 各自标来源 + `（待核实）`，不擅自定稿。
- **待补充**：项目笔记末尾清单，能补则补，不能补注明「等 X 之后」。

## E. 沉淀决策树

```
这个方法/经验，三个月后还会用吗？
├─ 不会 → 不沉淀，留在每日记录
└─ 会 → 是否已验证（真跑过、有结果）？
    ├─ 没有 → 进 _索引「候选方向」排队
    └─ 有 → 是否已有同主题一篇？
        ├─ 有 → 合并进那篇，更新「更新」日期
        └─ 没有 → 新建 50-沉淀库/主题.md，开头写「来源：Wxx 复盘 / 日期」
```

## F. 收尾

- 更新 `40-周复盘/_索引.md`（周次 + 一句话）。
- `00-首页.md` 变更日志追加一行；待办区按 P0 刷新。
- 项目笔记补「周维度小结」一段（不要复制复盘全文）。
- git 提交：`git -C <库根> commit -m "周复盘 2026-W45"`。

## G. 反面样例

- ❌ 把一周所有提交、所有版本号都列进「主线」→ 读者抓不到重点。
- ❌ 下周计划写「继续推进项目」→ 不是计划，是口号；要写「把 v3.12.0 提审，回填构建号」。
- ❌ 和上周完全一样的卡点、没有任何动作说明 → 要么升级为 P0，要么明确「本周不处理」。
