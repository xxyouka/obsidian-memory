# 写入规范 · 具体写法

## 1. Frontmatter

```yaml
---
tags: [每日记录]        # 每日记录 / 周复盘 / 项目 / 索引 / 沉淀 / 规程
日期: YYYY-MM-DD        # 每日记录用
周次: YYYY-Www          # 周复盘用
创建: YYYY-MM-DD        # 建文件那天，永不改
更新: YYYY-MM-DD        # 每次改内容都要改
---
```

- 键名全程统一，不要一半中文一半 `created` / `updated`。
- 模板、索引可以不带 `更新`；一旦改了内容就补上。

## 2. 双链与路径

- 写法：`[[20-项目/项目名|项目名]]` —— 路径相对库根，别名给人看。
- 表格里的双链要转义竖线：`[[20-项目/项目名\|项目名]]`。
- 链接目标必须真实存在；写完跑一遍体检脚本。
- 引用外部资料给**路径**，不复述内容。

## 3. 只写变化点

- ✅ `v3.12.0 提审通过，构建号 2026110501`
- ❌ `v3.12.0 是当前最新版本，包含反馈闭环、数据面板、权限系统……`（全貌已在项目笔记里）
- 数字必须可回溯：版本号、提交短号、文件大小、金额、用例数。

## 4. 待核实

- 证据不全的结论一律标 `（待核实）`，并在体检 / 复盘里列出来。
- 两个矛盾说法：并列 + 各自标来源，别二选一定稿。
- 用户后来改口属于**正常信息更新**，不算「写错」。

## 5. 口径更正

- **历史日记 / 历史复盘不改原文**，保留当时的认知。
- 更正写三处：① 新一天的每日记录里写「更正：…（原 X 作废）」；② `00-首页.md` 变更日志加一行；③ 涉及的角色 / 项目笔记直接改成正确口径。

## 6. 隐私与凭证红线

- 他人隐私不提炼、不外传；能抽象就抽象（「某同学」「某同事」「某班」）。
- 不写入：密码、token、密钥、证件号、手机号、住址、真实姓名（尤其要进公开仓库时）。
- 群聊 / 私聊只留「谁在什么场景提了什么诉求」，不留原话。

## 7. 文件与命名

- 每日记录：`30-每日记录/YYYY-MM-DD.md`（一天一篇）
- 周复盘：`40-周复盘/YYYY-Www.md`
- 沉淀：`50-沉淀库/主题.md`（中文短语，不用日期）
- 项目：`20-项目/项目名.md`
- 收件箱：`99-收件箱/YYYY-MM-DD-主题.md` → 归档到 `_已处理/YYYY-MM/`
- 不建 `未命名`、`新建笔记`、`副本` 这类文件。

## 8. 提交信息

```powershell
git -C D:\记忆库 add -A
git -C D:\记忆库 commit -m "每日整理 2026-11-05"
git -C D:\记忆库 commit -m "周复盘 2026-W45"
```

- 一次整理一次提交，别攒。
- 提交失败（权限、身份未配置、远端冲突）→ 在回复里说清楚，不要静默失败。
