# 好 / 坏样例（照这个写）

> 样例是通用化的，换成你自己的项目即可。

## 1. 每日记录 · 好

```markdown
## 🔄 项目变动
- **登录模块：换成短信验证码登录。**
  - 原因：老用户反馈记不住密码，客服每周约 20 单。
  - 落点：`src/auth/` 重写，`v2.3.0` 已上预发；线上仍走密码登录。
  - 数字：验证码到达率 98.2%（1,000 次抽样）。
```

好在哪：**有决定、有原因、有落点、有数字**。三个月后能照着复现，也能判断「要不要回滚」。

## 2. 每日记录 · 坏

```markdown
## 🔄 项目变动
- 今天搞了登录，改了一些代码，试了一下好像可以了，后面再看看。
```

差在哪：没有路径、没有验证结论、「好像可以」等于没记；「后面再看看」不是待办。

## 3. 待办 · 好 / 坏

- ✅ `- [ ] 预发环境补一次 1,000 次验证码到达率抽测（演示前）。`
- ❌ `- [ ] 继续优化登录。`（无验收标准、无时限）

## 4. 周复盘「净变化」 · 好 / 坏

| 写法 | 内容 |
|---|---|
| ✅ | 注册转化 41% → 53%；接口 P95 820ms → 210ms；线上 bug 3 → 0 |
| ❌ | 本周继续迭代，用户体验更好了 |

净变化必须是**可核对的两个数**，不是形容词。

## 5. 卡点 · 好 / 坏

- ✅ `**上线卡在审核**：应用商店要求补隐私政策链接，已提交两次都被打回；不补就赶不上 11-20 的推广节点。`
- ❌ `审核有点问题，需要处理。`

## 6. 「记住」即时落盘 · 示例

用户：「记住，以后交付都给我成品，别给一堆选项让我挑。」

动作：

1. 打开 `10-核心记忆/偏好与沟通风格.md`，在「交付偏好」下加一条：
   `- 要成品不要选项清单：直接给可用的版本，备选方案最多一句带过。`
2. 改 frontmatter `更新: 2026-11-05`。
3. 回复：「记在 `10-核心记忆/偏好与沟通风格.md`（交付偏好），今晚整理会再核一遍。」

反例：只回「好的，记住了」——下次会话它就没了。

## 7. 数据不进库，只进结论

- ✅ `本月退款 37 单 / 4,820 元，集中在尺码问题`
- ❌ 把 37 行退款流水贴进笔记

结论 + 总量 + 出处就够了，明细留在原始表格里。
