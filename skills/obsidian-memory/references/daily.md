# 每日整理 · 逐项清单

> 目标：一天一篇，写清「今天发生了什么变化 + 结论 + 下一步」，让三个月后的自己和任何 Agent 都能读懂。

## A. 输入盘点

1. `99-收件箱/` 下所有非目录文件（排除 `_说明.md`、`_已处理/`）。
2. 本次会话里出现的：决定、版本号、提交号、金额、日期、外部反馈。
3. 如果你同时用多个 Agent（Claude Code / Codex / Cursor / Trae / DSH…），把它们当天的会话汇编合并；同一件事只写一条，取信息最全的那份。
4. 只读**今天涉及**的项目笔记；没涉及的一律不打开。

## B. 判定是否要写

| 情况 | 动作 |
|---|---|
| 有决定 / 有进展 / 有新的待办 | 写 |
| 只有寒暄、重复已知信息 | 跳过，回一句「今日无新记忆」 |
| 信息不确定 | 写，标 `（待核实）` |
| 涉及他人隐私 | 不写具体人，只写「某同学 / 某同事」 |

## C. 成品骨架（复制即用）

```markdown
---
tags: [每日记录]
日期: YYYY-MM-DD
创建: YYYY-MM-DD
更新: YYYY-MM-DD
---
# YYYY-MM-DD 每日记录

## 📮 沟通要点
- 谁、什么事、结论（一句一条）

## 🔄 项目变动
- 项目名：变化点（版本 / 数字 / 状态变化，只写差）

## ✅ 完成 / ⏳ 待办
- [x] 已完成的事
- [ ] 未完成的事（带责任人或截止日）

## 🧷 备注
- 来源：收件箱文件名 / 会话 / 其他
```

## D. 追加规则（同日第二次整理）

- 不新建文件；在对应小节下继续加条目。
- 只改 frontmatter 的 `更新`，`创建` 不动。
- 推翻了当天早些时候的判断 → **不删旧条目**，加一行「更正：…（原判断作废）」。

## E. 同步到项目笔记

1. 先读目标项目笔记的「当前状态 / 进展」段。
2. 变化写成一条时间线项：`- 11-05：v3.12.0 提审通过，构建号 2026110501`。
3. 改 frontmatter `更新: YYYY-MM-DD`。
4. 状态变了才动 `20-项目/_项目总览.md` 的状态列。

## F. 归档

- `99-收件箱/foo.md` → `99-收件箱/_已处理/YYYY-MM/foo.md`（月份按**投递日期**）。
- 归档前确认：内容已被每日记录或项目笔记吸收。

## G. 「记住」这类即时投递

用户当场说「记住 / 记一下」时，不等晚上：

| 内容 | 直接写进 | 还是收件箱 |
|---|---|---|
| 一句偏好、禁忌、沟通习惯 | `10-核心记忆/偏好与沟通风格.md` 或 `雷区与红线.md` | — |
| 某项目的事实 / 决定 / 新待办 | 对应 `20-项目/*.md` | — |
| 跨项目、来源不清、还没想好放哪 | — | `99-收件箱/YYYY-MM-DD-主题.md`（新建） |

落盘后回复「记在 `<路径>`」，并说明当晚整理会吸收。**不要只回「好的，记住了」。**

## H. 交付给用户的回复（模板）

```
已整理 2026-11-05：新建 30-每日记录/2026-11-05.md；同步 <项目A> / <项目B> 两篇；收件箱归档 2 篇；1 条标（待核实）。已提交 <commit 短号>。
```

git 不可用就写「未提交（原因）」。
