# 📐 读取与更新规程

> 目的：**减少冗余读取**——每次只读任务需要的分区，读完把新结论写回，下次不用重复研究。

## 〇、记忆守则（最高原则）

- 本库是 {{OWNER}} 托付给 AI 的**长期记忆本体**：需要任何背景（人、事、项目、偏好、历史）时，**先去本库找**，别凭印象猜。
- {{OWNER}} 说「**记住** / 记一下 / 帮我记下」时：**必须落盘**（先落 `99-收件箱/`，或直接写对应分区），并在回复里说明记在哪；**口头答应不算记住**。
- 维护好本库是职责：保持结构、日期、链接整洁；发现过时信息随手修。
- 不确定值不值得记：先落收件箱留痕，整理时再筛。

## 一、按区读取（任务 → 读什么）

| 任务类型 | 读什么 | 不读什么 |
|---|---|---|
| 某人对话 / 个性化 | `10-核心记忆/偏好与沟通风格.md`、`雷区与红线.md` | 项目区、日志区 |
| 做某个项目的事 | `20-项目/_项目总览.md` → 对应项目笔记 | 其他项目、外部源码（除非需要） |
| 问最近发生了什么 | `30-每日记录/` 最近 3~7 天 | 全部日志 |
| 阶段性回顾 | `40-周复盘/` 最近 2~4 周 | 每日明细 |
| 深度方法 / 背景 | `50-沉淀库/` 相关文章 | 原始资料 |
| 收到新信息 | 先落 `99-收件箱/` | 直接改正式笔记 |

**层级**：首页(L0) → 分区索引(L1) → 单篇笔记(L2) → 外部原始资料(L3)。
**纪律**：同一信息只存一处；更新前先读再改；改动写日期；**不要整库重读**。

## 二、每日整理

**输入**：`99-收件箱/` 当天投递 + 当天对话中提到的项目信息。

1. 读当天收件箱内容 + 受影响的项目笔记现状（只读涉及的）；
2. 生成/追加 `30-每日记录/YYYY-MM-DD.md`（模板 `90-模板/每日记录模板.md`）：沟通要点 / 项目变动 / 待办 / 备注；
3. 把**变化点**同步到 `20-项目/` 对应笔记，更新 frontmatter `更新`；
4. 更新 `20-项目/_项目总览.md` 的状态列（有变动才改）；
5. 已整理的收件箱内容移到 `99-收件箱/_已处理/YYYY-MM/`；
6. 值得沉淀的深度内容 → 记进 `50-沉淀库/_索引.md` 候选。

## 三、每周复盘

1. 通读本周 7 天 `30-每日记录/`；
2. 生成 `40-周复盘/YYYY-Www.md`：本周主线、各项目净变化、卡点、下周计划、沉淀候选；
3. 把净变化合并进对应项目笔记（周维度小结）；
4. 有普适价值的写进 `50-沉淀库/`（一个主题一篇，别堆料）；
5. 健康检查：断链、过时信息、重复内容、待补充清单刷新。

## 四、写入规范

- frontmatter 带 `更新: YYYY-MM-DD`；
- 双链用 `[[路径|别名]]`；表格里竖线写成 `\|`；
- **不粘贴大段原文/聊天记录**，只留要点 + 出处；
- 隐私：他人隐私不提炼、不外传；密码/token/证件号一律不写入。

## 五、机器侧

- 技能：`obsidian-memory`（建库 / 每日 / 周复盘 / 体检）；装了就优先按技能执行。
- 体检：`scripts/check-vault.ps1`（断链 / frontmatter / 缺口 / 索引）。
- 本库是 git 仓库：重要更新后提交一次。
